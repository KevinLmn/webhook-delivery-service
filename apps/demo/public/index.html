Every request carries webhook-id, webhook-timestamp and an HMAC-SHA256 webhook-signature. The endpoint verifies it in constant time before answering, exactly like a production consumer should.

1 Idempotent ingestion

POST /events requires an Idempotency-Key. The API stores the event in Postgres, enqueues it and answers 202 immediately: delivery is asynchronous.

ingestion.ts

2 Signed delivery

The worker signs id.timestamp.body with the endpoint's secret (stored AES-256-GCM encrypted) and logs every attempt, success or not.

deliver.ts

3 Retries with backoff

5xx, timeouts and network errors are retried: 1 s, 10 s, 1 min, 10 min, 1 h, 6 h, with ±20% jitter. 429 Retry-After is honoured.

backoff.ts

4 Circuit breaker

5 failures in a row open the breaker for 30 s (doubling on relapse). Deliveries are postponed, not attempted. Then one probe goes through (half_open). State lives in Redis, updated by an atomic Lua script shared by all workers.

record_outcome.lua

5 Dead letters

A 4xx means the endpoint is alive but refuses this payload: retrying won't help. The event goes straight to dead, and can be replayed manually later. 1 event in 25 here is built to be rejected.

classify.ts
